# Spanguard — SPEC

**Repo:** `Hisernberg/spanguard` · **Model:** `Nabidnur/spanguard-span-xlmr-base` · **Meta Global AI Hackathon 2026** (Indie / Track 2, Dev Tooling + agent security)

## One-liner

An OpenAI-compatible security gateway for AI agents that reads **tool output the way an attacker writes it**: it finds prompt-injection spans inside the data coming back from tools, documents and MCP responses, and **strips the attack while keeping the data** — with a small open-weights model trained on Meta's Muse Spark Open labels, and a benchmark where it beats Meta's own Llama Prompt Guard 2.

## Why this (differentiation vs the 825-repo field)

- **Different from pii-guard (#1, 9.9):** pii-guard guards *outbound privacy* (mask PII before it leaves). Spanguard guards *inbound integrity* (strip injections coming back from tools). Different threat, different mechanism (irreversible strip vs reversible mask), different ML formulation (BIO span tagging of attack text vs NER for personal values), different competitor set (prompt-injection classifiers incl. Meta's own models, not privacy tools).
- **Different from the 9 named competitors:** veil/only-you/athos/wegweiser/iussum/Expectrail/stint/oqed/matrix-globe — none does span-level injection stripping on the tool→agent channel.
- **Timely:** agents ingest untrusted tool output (web fetch, files, MCP, RAG). Indirect prompt injection is the top agent-security failure; existing detectors are binary (reject the whole block → agent loses the data) or chat-prompt-trained (miss tool-shaped attacks).
- **The pii-guard playbook, applied:** small fine-tuned open-weights models (distilbert-base-multilingual 135M + a 0.79M char conv net, CPU-fast) ← teacher labels from a Meta open-weights model (Muse Spark Open on Baseten); committed benchmark runs vs open baselines; regression gates in CI; gateway you wire in by changing one base URL; live demo; Docker; tests.

## The benchmark — "Agent Tool Injection" suite

Fixture sets (fictional data only):

| Set | Docs | Origin |
|---|---|---|
| `handwritten` | ~60 (en/de/hu) | hand-written attacks, novel phrasings, no templates |
| `agent-traffic` | ~800 (en/de/hu) | synthetic tool outputs, planted + teacher attacks |
| `public` | converted | public prompt-injection dataset (binary), converted to spans |

Systems compared: **Spanguard fast** (rules+model), Spanguard rules-only, Meta Llama Prompt Guard 2 — **license-gated on HF; our download attempt returned 403** and no head-to-head run is claimed (published AgentDojo figures cited instead), `protectai/deberta-v3-base-prompt-injection-v2`, regex baseline, LLM self-detection (Muse Spark Open asked to detect).

Metrics: **leak rate** (planted attack payloads still readable after stripping), **over-stripping** (benign chars removed), doc P/R/F1, **CPU latency p50**. Committed run records (`eval/results/<date>-<run>/`), regression `gates.json` enforced in CI, README blocks generated by `spanguard eval report`.

## Architecture

```
agent ──> spanguard gateway (OpenAI-compatible /v1/chat/completions)
             │  walks messages: system/user inspected; assistant pass-through;
             │  tool-role messages (tool results) fully inspected
             ├─ rules  (fast patterns: overrides, tag forgeries, encodings, unicode)
             ├─ model  (BIO span tagger, 512-token sliding window, CPU)
             └─ audit  (opt-in Muse Spark Open deep scan)
             → strips spans → ⟨stripped⟩ markers → forwards upstream
```

Modes: `rules` (zero-dep, stdlib) / `fast` (rules+model) / `audit` (+LLM).
